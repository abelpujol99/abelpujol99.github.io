Devices Profiles GUI - WIP

Devices Profiles GUI is a desktop application. Its purpose is to remap any button's input from any peripheral that the user desires.

This application is being developed in C++, with the library ImGui and GLFW, and works only on Linux.

Backend

My design consists of giving the user the ability to activate 3 types of commands that they choose themselves when interacting with the button. Those commands are: emit input events, switch to a sub-profile and shut down the service itself.

Those commands can be triggered on the 3 states of a button: press, hold, and release.
When pressed or released, the chosen command will be triggered just once, but when holding that command will be triggered indefinitely inside a thread until the button is released. To avoid overwhelming the thread, the re-trigger time has a cooldown that has to be set by the user with a minimum value.

Creating threads is expensive, so, there's only 1 thread that manages the holding commands and is created at the start of the application. At this moment, when a hold command tries to be executed when another is already running, the older one will be stopped and let the new one start.

EmitInputCommand

This command allows the user to chain as many button inputs as they want, these inputs could be from the mouse, keyboard, or controller.

SwitchSubProfileCommand

In my design each peripheral can have more than one remapping profile, each profile can store a large amount of sub-profiles, and each sub-profile stores the inputs' remapping.

This command allows switching between sub profiles. When the button is pressed, the main sub-profile would be changed for the desired one, and vice versa when released.

ShutdownApplicationCommand

This command will shutdown the backend service, but not the application's frontend.

Frontend

This part of the application would manage the save files that contain the data and an interface to ease the remapping configuration.

ImGui

I decided to use ImGui because I saw good reviews about it due to its flexibility, modularity, and compatibility, and I thought it could fit the application's needs.

The usage I'm giving to this library is to display my own UI elements. Those elements were developed during this application through reverse-engineering of the most known videogame engines like Unity and Unreal.

Devices

In order to create the peripherals' profiles, the application needs to know the devices. To achieve this, the application reads the devices that are connected to the system and filters for those that are compatible with the application's purpose.

Why Linux?

When I used Windows, I downloaded an application that remapped my mouse's inputs, but when I switched to Linux, I couldn't find any software that satisfied me, so I decided to develop my own one that would cover everything I might want.
